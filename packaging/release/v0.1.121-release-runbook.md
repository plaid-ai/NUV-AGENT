# NUV Agent v0.1.121 secure release runbook

This runbook is intentionally fail closed. A pushed tag is only a release
request. It never receives release credentials. The actual publisher is
started by `workflow_run`, whose workflow definition comes from the protected
default branch, or by a manual dispatch whose ref is exactly `main`.

```text
signed v* tag
  -> release-request (read-only, no secrets)
  -> default-branch release-publish workflow
  -> signed-tag/main/settings preflight
  -> keyless tests + sdist + native arm64 bundle/DEB
  -> protected environment finalizes an immutable GitHub source release
  -> protected Homebrew environment promotes the exact formula
  -> protected APT environment publishes with previous DEB rollback access
  -> immutable distribution promotion marker
  -> protected manual IQ9075 environment
  -> signed-BOM verification + global sequence reservation
  -> BOM/bundle publication
  -> immutable OTA promotion marker
```

An artifact is not promoted when the final promotion marker is absent, even if
an earlier channel contains staged bytes. GitHub becomes immutable before a
live package channel changes. Failures before that transition preserve both
live channels; post-transition Homebrew/APT steps are byte-bound and rerunnable.
All trusted publisher runs share one global concurrency group because Homebrew
and APT have mutable channel pointers; different version tags cannot publish
those channels concurrently.

### Optional IQ9075/OAK media qualification

When a release explicitly claims OAK media stability, use the reviewed
`candidate-soak` primitive rather than an ad-hoc SSH probe. Run a signed
`oak-fault-rollback` to completion first, then invoke `candidate-soak` with the
same run ID and output directory. The
root-owned board tool requires a terminal rollback with no health deadline,
stages the exact authenticated BOM under `candidates/<runId>-<bomhex>`,
quiesces Agent/updater writers, runs the fixed installed 120-second harness,
preserves raw evidence before restoration, and proves exact slot/anti-replay
stability plus a fresh baseline PID before success cleanup. Do not directly
extract a bundle, run the soak over SSH, alter `current`/`previous`, or stop the
production Agent by hand.

The first root-owned recovery guard is armed before the emergency archive or
any trust snapshot is written. Its four-hour systemd monotonic deadline spans
`run`, the separate `candidate-soak` invocation, and the canonical cleanup
receipt. The journal binds a fresh writer epoch to the controller PID, Linux
process start ticks, and boot ID; stale callbacks cannot fence a reused PID.
The shorter OAK and candidate deadmen remain subordinate guards and do not
replace this transaction owner. Do not stop, reset, or recreate any of these
transient units by hand. If the transaction timer is missing, its remaining
monotonic lifetime cannot cover candidate recovery, or the board reboots, the
workflow fails closed and must converge through `cleanup`/boot reconciliation.
Deadline admission reads systemd's typed `NextElapseUSecMonotonic` `uint64`
over the local D-Bus API; human-readable `systemctl show` timespans are not
accepted as arithmetic evidence. Transaction and candidate recovery services
retry every 15 seconds without a systemd start-limit burst cutoff, while each
individual attempt remains bounded by its explicit `TimeoutStartSec`.

Every package installs and enables
`nuvion-fleet-e2e-reconcile.service`. Agent, updater service, and updater socket
all require this hardened root oneshot and start only after it succeeds. The
reconciler stops any live trust consumers before parsing persistent state,
strictly validates the root-owned active lease and run journal, restores and
verifies production bytes without starting runtime units, purges snapshots,
archives, candidate trees, and staging, fsyncs cleanup, releases the lease, and
only then finalizes the deadmen. Corrupt/missing/ambiguous state leaves all
three endpoints down. Package upgrade/removal runs the installed reconciler
before the fixed recovery tool can be replaced or removed; never bypass a
failed `prerm` or `postinst` gate.

Package scripts hold the same global Fleet lock used by the board tool, stop
all protected writers, and keep a root-owned, fsynced maintenance marker until
reconciliation and endpoint activation finish. The first upgrade from a
legacy package aborts if an active Fleet lease exists. With no active lease,
`preinst` atomically replaces the legacy fixed-path helper with a fail-closed
blocker before releasing the lock; unpack installs the marker-aware helper,
and `postinst` removes the private backup only at the final marker commit.
Failed install/upgrade rollback restores the exact root-owned legacy helper.
`dpkg --configure -a` recreates the marker, re-quiesces writers, and resumes
idempotently after any ordinary postinst failure.

### Candidate-soak trust boundary

The beta gate treats a publisher-signed candidate whose artifact, source SHA,
BOM, and release marker all match the release trust root as trusted but
fault-prone code, matching the production OTA trust model. The root-owned outer
collector—not candidate JSON—attests the minimum 120-second monotonic runtime,
systemd terminal status, continuous `nuvion` UID cgroup confinement, recursive
cgroup teardown, and exact production trust restoration before the board lease
is released. Candidate archive metadata/decompression and runtime resources are
hard bounded; `LimitCORE=0` also prevents native-process crashes from creating
host-side core dumps outside the candidate output and tmpfs quotas. The board
tool, host runner, SSH/sudo askpass child, transient recovery services, and
packaged boot reconciler all set a fail-closed zero soft/hard core limit before
reading password, keyring, configuration, or snapshot material.

A compromised publisher/signing key and deliberately malicious signed code are
outside this beta gate's containment claim. In particular, unrestricted
protocol egress needed by STOMP/WebRTC and intentional persistent OAK firmware
or calibration writes remain residual risks and require signing-key incident
response plus hardware re-provisioning. Do not describe the candidate sandbox
as a defense against a malicious trusted publisher.

## Partial failure and rerun rules

- GitHub draft/finalization failure: Homebrew and APT have not run. Correct the
  cause and rerun the same signed tag from `main`; byte comparison either
  completes the exact draft or verifies the already immutable release.
- GitHub immutable but Homebrew/APT/promotion failure: the source release is
  permanent, while the distribution remains ineligible. Rerun the same signed
  tag. Homebrew rejects downgrades/different same-version bytes, APT preserves
  immutable pool/by-hash objects and publishes signed `InRelease` last, and the
  final promotion marker uses generation-match-zero CAS.
- Missing OTA promotion marker: the BOM/bundle are staged but BE must not issue
  them. Rerun the same tag and sequence; create-only byte comparison makes this
  idempotent.
- Existing different reservation, BOM, GitHub asset, or promotion bytes: stop
  as a release-security incident. Do not delete/overwrite/retag.
- A reserved sequence whose release can no longer be completed is not reused.
  Resolve the original release or perform an explicitly reviewed sequence-gap
  recovery change; do not manually delete the reservation.
- APT publishes the current DEB plus the highest authenticated lower version in
  its signed index. Pool retention alone is not accepted as rollback access.

The new publisher rejects every unsigned tag, including v0.1.120, before
credentials. GitHub immutability is not retroactive, so the already published
v0.1.120 release remains a read-only legacy rollback baseline and cannot be
rerun through this workflow. Rebuild or correction requires a new signed patch
version; v0.1.121 and every later release must be immutable.
