# IQ9075 OAK deadman startup failure — 2026-09-08

The physical run for component `84b8a59eecb0a5b5fc6a1413e9da202d5ce3ec28`
activated the candidate and reached `BOOT_HEALTHY`. Its OAK recovery process
could not finish starting: `Type=oneshot` made synchronous `systemd-run` wait
for the 120-second sleep to exit, exceeding the caller's 20-second deadline.
Systemd also confirmed that `RuntimeMaxSec` has no effect for this service type.
The intended USB unbind follows this startup check and was not reached.

Use `Type=simple` for this sleeping recovery process. It becomes active while
the fault controller runs, retains `ExecStopPost` cleanup and the runtime/stop
deadlines, and still must pass the existing active-state check before USB writes.
Timer-triggered transaction recovery units are unchanged.

The test runner now models synchronous oneshot sleep startup instead of
immediately declaring every transient unit active. This reproduces the failure
before the fix; all 95 Fleet harness tests pass afterward. A separate, temporary
IQ9075 systemd service using `Type=simple` became active in 0.0204 seconds while
its three-second sleep was still running, and was then stopped and collected.
This smoke check did not touch the camera or execute an OTA command.

The failed physical chain is non-promotable. Its watchdog restored the previous
signed slot but the OAK health check failed; the original `ROLLBACK_FAILED`
journal and server `FAILED` command remain unchanged. The camera re-enumerated
as the USB2 bootloader during recovery. The fixed hardware probe booted the
camera while same-run cleanup waited for the exact original USB3 runtime port;
cleanup then returned `RESTORED` with all required absence proofs. The probe
itself was not a passing hardware acceptance result. Operational settings were
restored afterward and live video and continuous HTP inference were verified.

This change is not release readiness evidence. It requires a new immutable
component, signed candidate, and physical acceptance chain; neither the old
candidate nor the recovery receipt can serve as a passing rollback test.
